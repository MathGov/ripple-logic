## Executive conclusion

This release makes a bounded but material framework improvement. It preserves the governing cascade:

`RG -> RF/NCRC -> TRC -> CSV -> RLS`

It does not add a sixth gate, an eighth welfare dimension, a new authority source, or a competing decision engine. The substantive changes address four previously identified assurance weaknesses:

1. controls that exist but cannot act before unacceptable escalation;
2. responsibility that dissolves across human, model, vendor, committee, and operational handoffs;
3. a run validator that previously did not enforce its declared JSON Schema;
4. welfare evidence that could cross dimensions and Union Scopes without a dedicated boundary, interaction, dependence, subgroup, and migration standard.

## WDBIP placement decision

WDBIP v1.3 is included in the complete framework release as a **Canon-subordinate normative implementation companion beneath RLS**.

It is not one of the two principal governing sources. RippleLogic Canon v12.3 and SGP v8.2 remain the principal governing sources. WDBIP governs classification, evidence profiles, token-level interaction records, dependence disclosure, subgroup visibility, time-window discipline, weight sensitivity, and dimension-set migration for welfare evidence used by RLS. The Canon controls Union Scopes, admissibility, equations, weights, cascade semantics, and authority. SGP controls moral-patient evidence, protection, participation, power, and RMCP/P100 semantics.

WDBIP is included rather than released only as an external side package because its absence would leave a real integration seam in the active 7 x 7 welfare surface. Its source boundary prevents it from becoming a third governing core, a sixth gate, or an eighth dimension.

## Consequence-tempo correction

The release does not compare controls with the first material effect. It compares the **worst credible control critical path** with the earliest **unacceptable adverse escalation threshold or irreversible stop-loss boundary**.

For triggered actions, records disclose detection, interpretation, authorization, intervention, containment, safe-state transition, rollback or recovery, minimum/expected/worst-credible bounds, uncertainty, and serial or parallel dependencies. When runtime interruption is impossible, stronger ex ante assurance, bounded scope and rate, fail-safe behavior, and explicit residual-risk authorization are required. Harm caused by delay must also be compared.

# v12.0 Physical Admissibility Release Report

This report records the v12.0 release work.

## Accepted improvements

The release accepts the scientifically valid distinction that governance permission cannot by itself establish physical admissibility. A governance process may say that an action is approved, documented, certified, monitored, or authorized. That does not by itself show that the physical action is safe inside a mechanical, biological, infrastructural, medical, cyber-physical, or ecological regime.

## MathGov-native integration

The improvement is integrated in MathGov-native terms:

- PC-AEP v2.0 records physical/causal model, validity domain, boundary conditions, uncertainty, failure modes, reversibility, warrant, monitoring/shutoff path, residual unknowns, and claim action.
- CSV Gate Standard v2.0 consumes PC-AEP when physical execution is material.
- The Agent System v12.0 must not treat runtime `ALLOW` as physical-safety proof.
- ripple.md v5.2 must disclose when a Decision Note has governance permission only rather than physical admissibility evidence.
- The Canon v12.0 states that MathGov can require and audit physical-admissibility evidence but does not compute physics or certify physical safety.

## Rejected overclaims

- MathGov does not become a physics engine.
- MathGov does not become a formal-methods prover.
- MathGov does not replace medical, engineering, aerospace, robotics, infrastructure, or regulatory domain methods.
- Governance is not dismissed. Governance remains necessary, but it must not masquerade as physical proof.

## Release synchronization

All active core pins were moved to the v12.0 line or their designated round-number component versions, including SGP v7.0, Primer v4.0, ripple.md v5.2, Aligners Sheet v5.0, and compact standards v2.0.

# Governance-Parameter Attack Model

**Status:** Informative adversarial-conformance companion. It does not change the cascade.

## Core threat

Once a favorable score cannot rescue failed reality, rights, ruin, or viability checks, manipulation can move upstream into how the run is configured. The attacker may be an AI system, analyst, sponsor, institution, reviewer, regulator, vendor, or coalition.

## Attack classes and required response

| Surface | Attack pattern | Required control | Failure response |
|---|---|---|---|
| Scope | Omit an affected scope, future generation, ecosystem, or cross-border dependency | Stakeholder and dependency discovery, subgroup challenge, parameter lock | Reopen RG/CSV; invalidate if material omission remains |
| Evidence | Launder weak sources, suppress contradiction, convert unknown to zero, shift validity domain | Source hierarchy, evidence-status tokens, cutoff lock, dissent record | Narrow, escalate, or refuse |
| Rights | Relabel a protected right as a preference, average away the worst affected group, discount serious harm by confidence | Governed coverage sets, categorical and severe-hazard channels, worst-group review | NCRC_UNKNOWN or NCRC_FAIL |
| Tail risk | Omit ruin scenarios, split correlated pathways, shorten the horizon, redefine no-action | Versioned scenario library, dependence review, challenger log, Tail Emergency firewall | TRC_UNKNOWN/FAIL; no ordinary RLS |
| CSV | Declare dependencies immaterial, treat monitoring as control, treat permission as physical admissibility | Dependency graph, PC-AEP, source-coupling record, structural evidence | Redesign, control, escalate, or refuse |
| RLS | Tune weights after outcomes, change masks asymmetrically, shop MPS hypotheses, hide concentrated burdens | Parameter lock, HDW capture audit, active-mass checks, hypothesis sensitivity | Non-decisive, MPS_HYPOTHESIS_SENSITIVE, invalidate, or rerun |
| Authority | Choose a convenient reviewer, suppress minority reports, treat institutional rank as evidence, convert advice into permission | Separation of duties, conflict declarations, appeal, lawful mandate, revocation | No execution authority; escalate or refuse |
| Release | Alter a mirror, manifest, workbook, or website without matching hashes and pins | Single release manifest, current-pin verifier, hash replay | Release failure |

## Minimum adversarial suite

A serious Tier 3 or high-stakes Tier 2 implementation SHOULD test at least:

1. omitted vulnerable subgroup;
2. unknown-to-zero conversion;
3. categorical rights violation with strongly positive RLS;
4. low-probability catastrophic pathway omitted from the scenario library;
5. correlated tail events represented as independent;
6. structurally non-viable high-benefit option;
7. post-outcome weight change;
8. MPS hypothesis shopping;
9. authority laundering;
10. unsupported physical-execution claim;
11. persuasive but false PCC narrative;
12. stale package or component pin.

## Pass rule

The suite passes only when the expected block, uncertainty state, redesign, escalation, refusal, or authority limitation is produced and logged. A test that merely generates a warning while allowing ordinary RLS or execution is a failure when the relevant Canon rule requires a block.

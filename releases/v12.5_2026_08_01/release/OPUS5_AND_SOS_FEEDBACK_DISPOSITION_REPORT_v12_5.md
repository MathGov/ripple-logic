# MathGov v12.5 — Opus 5 and SOS Feedback Disposition Report

**Release identity:** MathGov Core Release 2026.09 v12.5 / SGP v8.4  
**Patch type:** same-version scientific, exemplar, machine-interface, and verification hardening  
**Governing architecture preserved:** `RG -> RF/NCRC -> TRC -> CSV -> RLS`

## Executive verdict

The Opus audit identified several genuine specification-to-exemplar and machine-interface defects. They did not require a new gate, scope, welfare dimension, right, SGP protection rule, or component version. The valid findings were corrected together so that the Canon, worked vectors, workbook, run-record states, DOCX/PDF mirrors, schemas, and verifiers now express one operative system.

The SOS writing contributed one bounded improvement: governance must not imply that policy, approval, certification, risk acceptance, or responsibility assignment reduces an unknown physical operating envelope. MathGov already separated governance permission from physical admissibility; the present patch makes the unknown-envelope action boundary explicit. Governance may authorize bounded learning actions only when those actions themselves qualify through rights, ruin, and structural-viability review.

## Findings integrated

1. **RLS uncertainty implementation.** The Aligners Sheet had treated `sigma_est = 0.02` as an already aggregated option-level `sigma_RLS`. The Canon requires cell-level uncertainty to be aggregated through the active effective weights. The repaired workbook computes `sigma_RLS = 0.0031817987`, `Gap = 3.5655178`, and the technical verdict `DECISIVE`, selecting Option A within the declared worked-run assumptions.
2. **Method B reconstruction.** Canon Section 10.3.2 now states explicitly that a single-instance post-confidence saturated impact must reconstruct pre-confidence mass as `atanh(I_prop_welfare)/(beta*c_k)`. Appendix P now reports `sigma_RLS(B) ≈ 0.000952`, consistent with the normative rule and Appendix R.
3. **Audit-flag closure.** Added `CANONICAL_AUDIT_FLAG_REGISTRY_v1.0.yaml` and `VERIFY_AUDIT_FLAG_REGISTRY.py`. The machine registry contains 67 controlling tokens and the verifier rejects controlling tokens missing from either the registry or Canon.
4. **Severe-rights materiality and examples.** Added an option-relative materiality screen, evidence-bound `NOT_MATERIAL` rationale, tolerance provenance, and both failing and passing severe-hazard examples. No universal `rho_r` was introduced.
5. **Containment conformance vector.** Replaced the obsolete `Anc(U4,D_c)` construction with an explicit decision-specific dependency graph `G_c` and `Contain(U4,G_c)`.
6. **Tier 1 CSV.** Corrected the PCC tier matrix so Tier 1 requires a brief CSV screen or an evidence-backed `CSV_NOT_MATERIAL` rationale before ordinary ranking or selection.
7. **Appendix P Option C.** Replaced the unexplained CSV exclusion with named `SV-2` and `SV-3` defects, absent control IDs, and a defined requalification path.
8. **Rights-floor construction.** Worked examples now state that `I_RF_base` is independently constructed with `tau_RF=1`; numerical equality with a welfare-stream value never establishes derivational identity.
9. **Kernel evidence eligibility.** QUICK propagation is prohibited when `C_cov < 0.40`, regardless of additive KQS, preventing field completeness and priors from compensating for inadequate evidence coverage.
10. **U1 scope meaning.** U1 is the affected-individual scope, not a privileged decision-maker-interest weight. Its floor rationale now protects person-level impact visibility.
11. **Provisional UCI symmetry.** Provisional UCI cannot be the sole basis for either a high-stakes failure or an unqualified high-stakes pass.
12. **Decision-state serialization.** Added one normative `FrameworkVerdict -> decision_state` crosswalk, added `NCRC_UNKNOWN`, and represented emergency-provisional action consistently in the Canon, Reproducibility Standard, schema, and canonical state registry.
13. **Stale references and precedence.** Repaired Mode A/Mode B pointers, moved notation and interfaces above worked vectors in the precedence hierarchy, clarified the foundation baseline date, marked Agent v12.3.1 language as lineage, and added ripple.md v5.3/v5.4 release deltas plus the controlling reconstructability hierarchy.
14. **Workbook implementation.** Corrected uncertainty aggregation, canonical gate tokens, WTSL mandatory-count logic, parameter notes, authority-selection applicability, subgroup-input disclosure, and the sanity-check headline while preserving the worked-run-exemplar claim boundary.
15. **Unknown-envelope governance boundary.** Added MathGov-native wording to the Canon, CSV, PC-AEP, MFDI, and ripple.md: policy or acceptance may allocate responsibility and govern bounded testing, but cannot be represented as physical evidence or as making an unknown envelope safe.

## Findings rejected or bounded

- **Missing release artifacts:** rejected. The full package contains genuine OOXML DOCX files, PDFs, schemas, validators, manifests, hashes, a license, RLS workbook, archives, and test vectors. The audit’s contrary findings arose from its partial extracted-text bundle.
- **Universal severe-hazard tolerance:** rejected. A universal `rho_r` would create unsupported cross-domain precision. Tolerances remain right-, event-, population-, domain-, and authority-specific.
- **“Medium uncertainty = user’s own risk”:** rejected where rights, non-consenting third parties, public safety, or ruin exposure are material. Consent cannot externalize or waive those obligations.
- **Engineering as complete decision authority:** rejected. Engineering evidence is indispensable for physical claims, but it does not by itself settle rights, legality, legitimacy, distribution, authorization, or democratic authority.
- **Universal deterministic-control requirement:** rejected. The required property is evidence-bound admissibility and enforceable control proportionate to stakes, not one universal computational architecture.
- **Categorical claim that current AI can only produce statistical correlations or cannot generate knowledge:** rejected as overbroad. Candidate-generation claims remain architecture-, task-, evidence-, and validity-domain specific.
- **Citation corrections proposed for Andrews et al., Butlin et al., and Pennartz:** rejected after verification; the release entries are accurate.
- **New component versions:** not applied by instruction. The patch is identified through package build identity, report, manifest, and hashes while all component versions remain unchanged.
